# 小学生字学习机

基于 Waveshare **ESP32-S3-ePaper-1.54G** 的离线生字学习设备：墨水屏展示生字（拼音 + 楷体大字 + 词组），语音交互。

## 硬件

| 项目 | 规格 |
|---|---|
| 主控 | ESP32-S3-PICO-1 (LGA56) rev v0.2，240MHz 双核 |
| 存储 | 内置 8MB Flash + 8MB PSRAM |
| 屏幕 | 1.54" 四色墨水屏 200×200（红/黄/黑/白）|
| 刷新 | **全局 20 秒 / 快速 15 秒** ← 决定了整个交互设计 |
| 音频 | ES8311 编解码 + 板载麦克风 + 板载扬声器 + PA |
| 其他 | Micro SD（FAT32）、RTC PCF85063、温湿度 SHTC3、锂电池管理 |
| MAC | `70:04:1d:d7:eb:04` |

### 连接与下载模式

S3 用原生 USB（直连 GPIO19/20），芯片在运行才会枚举成 `/dev/cu.usbmodem*`。

本项目固件常驻运行（要持续监听唤醒词），插上 USB 就能识别，
`idf.py flash` / esptool 会通过 USB-Serial-JTAG 自动复位进下载模式，不用按键。

本固件只有一种情况会让 USB 消失：插着 USB 时「关机」会进入深度睡眠（见[电源](#电源)），**按一下 PWR 就能唤醒**。

板子**只有 BOOT 和 PWR 键，没有 RST 键**。如果板子跑的是别的会 deep sleep 的固件（如官方墨水屏例程），
USB 会随之断电、插电脑不被识别，这时用官方方法「按住 BOOT，重新上电」：

```
拔 USB（接了电池要一起拔）→ 按住 BOOT → 插 USB → 保持 2-3 秒 → 松开
```

```bash
. ~/esp/esp-idf/export.sh    # IDF 5.5.1 自带 esptool v4：子命令和参数用下划线
esptool.py --port /dev/cu.usbmodem* --after no_reset flash_id   # --after no_reset 可保持端口不掉
```

## 设计要点

**墨水屏刷新要 15-20 秒**，所以：屏幕只做静态展示，**全部交互靠音频**。
切字时刷屏与朗读并行，把等待掩盖掉。这利用了墨水屏的长处（持久显示、零功耗、护眼），
避开了它的短处。

**图片格式**：直接生成显示驱动的原生缓冲（取自 `GUI_Paint.c` 的 `Scale==4` 分支），
4 像素/字节、高位在前、行主序，每张 **10,000 字节**。固件 `fread` 完直接 `epaper_port_display()`，
零转换。

> 不使用官方 `GUI_ReadBmp_RGB_4Color()`：它对奇数像素的取位有 bug
> （`temp = byte >> 0` 后 `temp >> 2` 会混入相邻像素的位）。

**音频格式**：16kHz / 16bit / **单声道** PCM WAV。codec 按双声道打开，
固件里实时把单声道复制成双声道 —— 用一点 CPU 换一半 SD 空间（335MB vs 670MB）。

> WAV 头不能写死 44 字节：ffmpeg 默认会在 `fmt` 和 `data` 之间插一个 LIST 元数据块
> （PCM 从第 78 字节才开始），跳少了会把元数据当声音播出一声「咔」。
> 固件按 RIFF 块结构找 `data` 块；`gen_audio.py` 也加了 `-fflags +bitexact` 生成标准 44 字节头。
> 已经做好的 SD 卡不用重新生成音频。

**离线语音**：esp-sr 单麦输入。板载喇叭和麦克风离得很近，朗读时必然被拾取；
拿不到播放端参考信号做 AEC，所以改为**朗读期间给 AFE 喂静音**，避免自激误唤醒。

### 应用层（M4）关键决策

- **学习状态只有一个主人**：语音、按键、串口控制台都只往一个命令队列投递，由 `cmd_task` 串行处理；
  刷屏在独立的 `display_task`。状态不用加锁，也不会两个来源同时改进度。
- **刷屏期间可以插队换字**：面板那约 20 秒的波形掐不断（固化在 OTP 里），但命令照常执行 ——
  换字排进深度 1 的显示队列（后者覆盖前者），这一张刷完直接刷最新的那个，查错了字不用干等它刷完。
  错字的笔顺朗读当场掐掉，同时回一句「等一下哦」，免得后面十几秒静音显得像死机。
  插队省掉的是错字的朗读和再喊一遍，不是那 20 秒。
- **进度存 NVS，不存 SD**：当前组（清单文件名）、当前字 id、掌握位图（2500 字 → 512 字节）、
  屏上的画面编码。NVS 写入断电安全，家长拔卡改清单也不丢进度；
  SD 上的 `progress.txt` 只是导出给家长看的。组按文件名记而不是序号，增删清单后仍回到原来那组。
- **开机不重刷**：墨水屏断电保持画面。NVS 记着屏上是哪张图（`字id×2 + 是否有红勾`），
  和要显示的一致就跳过刷屏，开机约 5 秒可用。刷屏前先把记录清成 -1，刷到一半断电下次会重刷。
- **红勾由固件画**：已掌握的字在大字右侧的空白处（x162-194, y50-80）叠加红色 ✓，不用再生成一套图。
- **复习不设模式**：「复习」= 跳到本组下一个没掌握的字；「我会了」= 标记后同样跳到下一个没掌握的字。
  孩子不用理解模式切换。本组都会了会提示「这一组都会了」。
- **查字不分组，对原始文本**：所有清单里的字都能直接查，像查字典一样。难点是 2500 字共约 1.4 万条
  「词的字」说法，MultiNet 一次最多注册 400 条，放不下。好在 MultiNet 不套命令词表、逐字听出来的拼音
  （原始文本）很准：「如果的果」→ `ru guo de guo`。所以命令词表只放固定命令，查字由固件自己比：
  取原始文本里最后的「de X」，跟所有以 X 结尾的说法（外加 lu、rou 这些容易听混的音节）逐条比，
  平均每个音节差得够少、又明显比别的字像，才算对上（两个字的词可以错一个字）。平翘舌、前后鼻音、n/l
  这类只算小差别。前两名差不多（比如只听到「guo de guo」）就说「没听清」，不乱跳。
  最大的一份是「的 ji」204 条。
  前提：所有说法都以「de <音节>」结尾，`gen_scopes.py` 生成的都是。对不上会说「没听清，再说一遍」。
  （试过常驻每个音节一条「de X」命令、听到后换上这一份重认，但这种短命令在句尾几乎不触发。）
- **等这句话说完再执行**：听到命令先不执行，等这句话说完、以最后一个结果为准。「说完」指原始文本 0.64 秒
  没再变；周围一直有人说话时，最多再等 1.5 秒。原因：「认识的认」会先听到「认识」（= 我会了），
  接着原始文本里才出现「的认」，这时查字优先。不看 VAD：实测 6 秒的窗口里它判人声 5.7 秒以上。
- **组只用来排顺序**：「下一个」到了组尾接着学下一组；查的字不在本组，就换到它所在的组。
  语音不能切组，控制台的 `g N` 还能切（调试用）。
- **连续对话**：执行完一条命令后继续听 6 秒，连着说「下一个」「再读一遍」不用每次喊唤醒词；
  时间到了静默回到待唤醒。只有唤醒后一句命令都没说才响「超时」提示。
  这 6 秒按送进识别模型的录音算，不按墙钟：播放期间不计时，算得慢也不会把还没算到的话当成超时。
- **识别算力**：唤醒词和命令词模型都在 CPU1 上跑。160 MHz / 32 KB 数据缓存时算不过来
  （任务看门狗报 IDLE1 饿死，唤醒后的话识别不出）。改用 esp-sr 推荐的 240 MHz + 64 KB 数据缓存，
  等命令期间关掉唤醒词模型。实测命令词模型只占实时的约 30%，最长一帧 16 ms（每帧 32 ms），
  缓冲从不排队。代价是用电池时更费电。
- **语音提示两级降级**：先找 SD 卡 `sys/<名字>.wav`（人声），没有就用固件合成的提示音，旧 SD 卡照样能用。

## 内容生成

需要 ffmpeg（`brew install ffmpeg`）。

```bash
cd content
uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python pypinyin jieba pillow edge-tts

.venv/bin/python build_data.py        # → out/chars.json
.venv/bin/python gen_images.py        # → 2500 张图（约 2 分钟）
.venv/bin/python gen_audio.py         # → 5000 段音频（约 80 分钟，可断点续传）
.venv/bin/python gen_scopes.py        # → 50 组学习清单（每组 50 字）
# 只改命令词、分组不变（手头只有 SD 卡时）: gen_scopes.py --rephrase <SD>/pinyin/scope
.venv/bin/python gen_prompts.py       # → 105 条语音提示（约 1 分钟，可选）
.venv/bin/python gen_stroke.py        # → 笔顺表 + 54 个笔画片段（约 1 分钟，可选）
.venv/bin/python pack_sd.py /Volumes/<SD卡名>
```

`gen_stroke.py` 读的是随代码提交的 `data/stroke_order.txt`，不联网取笔顺数据。
那个文件本身由 `gen_stroke_order.py` 生成，需要 npm 和一份 30MB 的字形库，很少需要重跑。

`gen_images.py` 可传汉字只生成样张：`gen_images.py 水 服 便`

已经做好的 SD 卡只需补语音提示和笔顺：跑 `gen_prompts.py` / `gen_stroke.py` 后把
`out/sys/`、`out/stroke/` 拷到 `<SD>/pinyin/` 下的同名目录（或重新跑 `pack_sd.py`，
它不会覆盖已有的 `config.txt`）。

## SD 卡结构

```
<SD>/pinyin/index.txt                 生字总数
<SD>/pinyin/chars.json                元数据（固件不读，便于排查）
<SD>/pinyin/img/0000.bin              10000 字节
<SD>/pinyin/aud/0000_c.wav            字音
<SD>/pinyin/aud/0000_w.wav            词组连读
<SD>/pinyin/scope/01_基础字1-50.txt   学习清单（语音命令词），按文件名排序 = 组的顺序
<SD>/pinyin/sys/busy.wav …            语音提示（可选，缺了用合成提示音）
<SD>/pinyin/stroke/bishun.txt         笔顺表（可选，缺了就不念笔顺）
<SD>/pinyin/stroke/s00.wav …          笔画名「横」「竖折折钩」等 29 个片段
<SD>/pinyin/stroke/n01.wav …          「一画」…「二十三画」
<SD>/pinyin/config.txt                设置（可选，见下文）
<SD>/pinyin/progress.txt              学习进度（设备写出，给家长看）
```

学习清单每行 `字id<TAB>汉字<TAB>命令词`，命令词是无声调拼音，多种说法用逗号分隔，
**每种说法都必须以「de <这个字的拼音>」结尾**（查字按最后一个音节分份，见上文「查字不分组」）：

```
<字id>	如	ru guo de ru,bi ru de ru,li ru de ru
```

家长可照此格式把课本单元的生字表写成清单放进 `scope/`，文件名前缀（`01_`、`02_` …）决定组的顺序。
文件名可以用中文（固件已开启 FATFS 长文件名 + UTF-8），最多 99 组。
所有清单合起来就是查字表；同一个字在几个清单里都有时，查字先看本组，本组没有就去它第一次出现的组。
SD 卡上一个清单都没有时，按字表顺序学全部 2500 字（这时只能按键 / 说「下一个」翻，不能查字）。

`progress.txt` 在进度变化后空闲 30 秒、以及关机时写出：总共会了多少字、当前学到哪，
以及每组已会几个、分别是哪些字。**只写不读** —— 改它没用，进度存在设备的 NVS 里。

## 固件编译

```bash
. ~/esp/esp-idf/export.sh          # ESP-IDF v5.5.1
cd firmware/pinyin_epaper
idf.py set-target esp32s3
idf.py build
idf.py -p /dev/cu.usbmodem* flash monitor
```

分区表按 **8MB flash** 排布：4MB 应用 + 3.9MB 预留给 esp-sr 语音模型。

`idf.py flash` 会连同语音模型一起烧（`srmodels.bin` → `0x410000`，约 3.3MB），不用单独烧模型分区。
只改了代码时用 `idf.py -p /dev/cu.usbmodem* app-flash`，只烧应用，快一半。
模型选择改在 `sdkconfig`（WakeNet / MultiNet），重新 build 会自动重新打包 `srmodels.bin`。

## 交互

开机后屏上还是上次学到的字（不用重刷），约 5 秒后语音就绪。

### 语音

说「**你好小智**」**或单击 BOOT** 唤醒（叮一声），6 秒内说命令。执行完后**继续听 6 秒**，
可以直接说下一条，不用再唤醒。周围吵、声音小的时候唤醒词不一定叫得醒，按键百分之百唤得上。

| 说法（任选其一） | 行为 |
|---|---|
| 「词 + 的 + 字」，如「如果的如」 | 查这个字，**不分组**：清单里的字都能查，跳到它所在的组 |
| 下一个 / 换一个 / 下一题 / 跳过 | 下一个生字（到组尾接着学下一组）|
| 上一个 / 回去 / 刚才那个 | 上一个生字 |
| 再读一遍 / 再说一遍 / 没听清 / 再来一次 | 重播字音 |
| 读词组 / 怎么组词 / 组个词 / 有什么词 | 播放词组 |
| 我会了 / 会了 / 认识 | 标记掌握（右上角画红勾），跳到下一个没掌握的字 |
| 复习 | 跳到本组下一个没掌握的字 |
| 忘了 / 我忘了 / 没记住 | 取消掌握标记（去掉红勾），再读一遍 |

每个字最多登记 6 个词：屏幕上的词，加上最常用的词（如「如」：如果、如何、比如、例如……），都是「词的字」这种说法。
想加自己的说法（如「云谷的谷」「女字旁的她」），写进 `content/data/phrase_extra.txt` 再重新生成清单。
想知道某个字能怎么说、在第几组，用[调试控制台](#调试控制台)的 `find` 和 `l`。

**查字说完停一下**：机器等你说完（约 0.6 秒没有新的字）再查，所以比别的命令慢一点。前面多说了什么没关系
（「你好小智，如果的如」也行），「的 X」后面带个「啊」也行。对不上会说「没听清，再说一遍」，
串口日志里能看到机器听成了什么（`原始:` 和 `查字` 两行，见下文诊断日志）。

**刷屏（约 20 秒）期间照样可以说话**：查错了字直接说新的，会听到一句「等一下哦」，
这一张刷完立刻刷新的那个，错字的笔顺朗读当场停掉。面板波形本身掐不断，所以省掉的是等待里的朗读，不是那 20 秒。

喊完「你好小智」，等「叮」响完直接说命令，不用再喊一遍：响铃和朗读的时候麦克风是关着的。

### 按键

| 操作 | 行为 |
|---|---|
| 单击 BOOT | **唤醒**，等孩子说话（等于喊「你好小智」）|
| 双击 BOOT | 下一个生字 |
| 长按 BOOT | 播放词组 |
| 单击 PWR | 我会了 |
| 双击 PWR | 复习 |
| 长按 PWR | 关机 |

最常用的单击给了唤醒：喊唤醒词不一定叫得醒，按键一定叫得醒。代价是**「重播字音」没有按键了**，
只剩说「再读一遍」和控制台的 `r`。按下时正在念的笔顺会立刻停掉 —— 按这个键就表示「我要说话了」，
而且朗读期间麦克风是关着的，不停掉根本听不见。已经在听的时候再按一次只是把 6 秒窗口续满，不会再响一次「叮」。

按键和语音、控制台走同一个命令队列，由 `cmd_task` 串行处理，不会互相打架；刷屏期间也照常执行（见上面的插队换字）。

### 语音提示

| 场景 | 文件（`<SD>/pinyin/sys/`）| 内容 |
|---|---|---|
| 唤醒 | `wake.wav` | 默认不生成，用提示音「叮」|
| 唤醒后没说命令 | `timeout.wav` | 默认不生成，用提示音 |
| 刷屏中又换了一个字（排队） | `busy.wav` | 等一下哦 |
| 我会了 | `mastered.wav` | 真棒！ |
| 忘了 | `forgot.wav` | 好的，再学一遍 |
| 本组没有没掌握的字 | `all_done.wav` | 这一组都会了，真棒！ |
| 查字没认出是哪个字 | `not_found.wav` | 没听清，再说一遍 |
| 控制台切组 | `group_01.wav` … `group_99.wav` | 第一组 … |
| 关机 | `bye.wav` | 再见 |

缺哪个文件就用固件合成的提示音代替（每种场景音调不同）。想换成家长录的声音，
录成 16kHz 单声道 WAV 同名替换即可。首尾别留长静音：播放期间设备听不见命令（防止自己的声音触发识别），
`gen_prompts.py` 也会把 TTS 自带的首尾静音裁掉（「真棒！」1.9 秒 → 0.7 秒）。

## 设置（config.txt）

放在 `<SD>/pinyin/config.txt`，没有这个文件就全用默认值；`pack_sd.py` 首次打包时会写一份带注释的默认配置。
改完重启设备生效，启动日志会打印实际生效的值。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `volume` | 100 | 音量 0-100，周围吵的时候 80 听不清提示音 |
| `wake_sensitivity` | high | 灵敏：唤醒阈值压到 0.45（模型自带 0.58）。常被别的声音误唤醒就改成 `normal`（用模型自带阈值，误唤醒少，但离得远、声音小时不容易叫醒）。注意别用 WakeNet 的 `DET_MODE_95` 来调灵敏度：wn10 切过去实测一次都叫不醒 |
| `mn_threshold` | 0 | 命令词识别阈值 0-1，0 = 模型默认。常把别的话听成命令就调高（如 0.3），说了没反应就调低（如 0.1）|
| `listen_seconds` | 6 | 唤醒后等命令的秒数（2-30）|
| `follow_up_seconds` | 6 | 连续对话：执行完命令后继续听的秒数，0 = 关闭（0-30）|
| `sleep_minutes` | 10 | 用电池时多少分钟没操作自动关机，0 = 不自动关机（0-240）|
| `stroke_order` | on | 刷屏时念笔顺。刷一次屏约 20.5 秒，字音 + 词组只占 4 秒，念笔顺把剩下的空档填上。四色波形的时长随温度变（同一块板实测到过 17.6 也实测到过 20.7 秒），固件每刷完一屏就把实测值回填，下一个字按真实窗口摊停顿 |
| `stroke_gap_ms` | 0 | 笔画之间停顿的毫秒数。0 = 自动：按这个字的笔画数摊，念完刚好赶上刷屏结束（夹在 250-2000ms）。填固定值（如 800）则笔画多的字会念到字出来之后（0-3000）|

调 `mn_threshold` 时看串口日志：听到固定命令会打印 `听到: "…" prob=…`。查字不走命令词表，不受这个阈值影响。

## 电源

板子的电池供电靠 GPIO17 自锁：按 PWR 时临时接通电源，固件启动后把 GPIO17 拉高「接住」。

- **开机**：用电池时按一下 PWR。
- **关机**：长按 PWR → 说「再见」→ 等刷屏结束（刷到一半断电屏会花）→ 导出 `progress.txt` → 断开自锁。
- **自动关机**：用电池时 `sleep_minutes` 分钟没有任何操作就关机；插着电脑时不会自动关机。
- **插着 USB 时**断不了电，「关机」改为深度睡眠：屏幕和音频断电，USB 端口消失，按 PWR 唤醒（重新启动）。
- 电池开机时 PWR 键本身就是按着的，松手 0.5 秒前的 PWR 事件都会忽略，免得开机那一下被当成长按关机。

## 调试控制台

不用对着设备喊也能测试：`idf.py -p /dev/cu.usbmodem* monitor` 里直接敲命令回车。
控制台和按键、语音走同一个命令队列，行为完全一致。

| 命令 | 作用 |
|---|---|
| `n` / `p` | 下一个 / 上一个（到组尾接着下一组）|
| `r` / `w` | 重播字音 / 读词组 |
| `m` / `f` / `v` | 我会了 / 忘了 / 复习 |
| `c 汉字` / `c 字id` | 查字，和说「如果的如」一样（如 `c 如`）|
| `py 拼音` | 把拼音当成机器听到的原始文本去查字（如 `py ru guo de guo`），日志列出最像的 3 个字，对上了就跳过去 |
| `gn` / `gp` / `g N` | 下一组 / 上一组 / 第 N 组（调试用，语音不能切组）|
| `k` | 按键唤醒，等于单击 BOOT（真的进监听窗口）|
| `wake` / `timeout` | 只播放唤醒 / 超时提示音，不进监听窗口 |
| `s` | 状态：位置、掌握数、电池电压、剩余内存 |
| `l` | 列出本组的字（字 id、是否掌握）和各自的查字说法 |
| `find X` | 在所有清单里找 X（汉字或拼音，如 `find 如`、`find ru guo`），显示在第几组、组内序号 |
| `export` | 立即导出 `progress.txt` |
| `off` | 关机 |

> sdkconfig 里主控制台是 UART0，USB 只是输出用的副控制台，stdin 读不到 USB 输入；
> 所以固件装了 USB-Serial-JTAG 驱动直接读，同时让日志也走驱动（否则两者抢同一个 FIFO）。

### 语音备注

唤醒词只能用乐鑫**预训练**的（「你好小智」「Hi 乐鑫」等），自定义需向乐鑫申请训练。
命令词（MultiNet）可自由定义中文短语，不受此限制，但一次最多注册 **400 条**。
2500 字的说法全注册会超限（约 1.4 万条），所以命令词表只放固定命令，
查字由固件拿原始文本去比（见上文应用层关键决策），说法条数不受 400 条限制。
`gen_scopes.py` 生成时会打印分份情况（按最后一个音节分多少份、最大的几份）。

查字说法怎么取词，见 `content/gen_scopes.py` 开头的说明，要点如下：
- 词的来源：屏幕上的词，加上常用词。常用词取自 jieba 词典，只取卡片上教的读音。
- 同音撞车（「由于的于」和「犹豫的豫」都是 you yu de yu）：屏幕词和人工加的词优先；
  两边都是常用词时，一个比另一个常用 100 倍以上就给常用的（「如果的如」不再被冷僻的「辱国的辱」挤掉），
  差不多常用就都不登记。不分组查字，所以全部清单一起算。
- 没有任何说法的字查不到，生成时会列出来，可以在 `data/phrase_extra.txt` 给它们加词。
- 为什么这样做：原来每字只登记一个屏幕词，常用词的覆盖率只有 14%（「如」只认「比如的如」，说「如果的如」没反应）。

**识别诊断日志**：每次等命令结束，串口打一行 `SR: 诊断[超时 / 识别到 / 连续对话]`，没识别到时看卡在哪一环：
- `听了 / 过了`：送进模型的录音时长 / 实际经过的时间。「过了」明显大于「听了 + 静音 + 等锁」，说明算力跟不上。
- `静音`：播放提示音、字音时麦克风关着的时长。`等锁`：重建查字表时录音排队的时长（开机时才有）。
- `MultiNet 占实时`、`最长一帧`（每帧 32 ms）、`缓冲最少剩`：看算力还有多少余量。
- `人声`、`峰值`：VAD 听到人声的时长和最大音量。「没有」说明没听到或声音太小。
  VAD 在有人说话时基本一直判人声，人声起点也会把唤醒词的尾巴算进去，只能粗看。

说了没反应，再看这几种日志：
- `原始: "…"`：MultiNet 逐字听出的拼音，每变一次打一行。先看它把话听成了什么。
- `查字「…」: 比了 … 共 N 条 → 对上了 / 对不上 / 说不准是哪个`：下面列出最像的 3 个字和「差」多少
  （0 = 一模一样，超过 0.34 算对不上，前两名差不到 0.04 算说不准；但第二名的说法更短、只对上了后半截时——
  「公交车的交」里的「轿车的轿」——算第一名）。
  听得对却对不上或跳错了字，用 `find` 看清单里有没有这个说法。
- `待唤醒: 听到 N ms 人声，峰值 X dB，没唤醒`：待唤醒时说了一段话却没唤醒（周围有人说话也会记）。
  喊了「你好小智」没反应、有这行，是唤醒模型没认出，离近点、说清楚点；连这行都没有，是声音太小没听到。
